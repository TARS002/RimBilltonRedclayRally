# 雷姆必拓红土拉力赛 · 项目启动与学习路线

> 一句话：一个**单人、非商业、low-poly 风格的拉力赛车游戏**，先做 PC 原型，目标是**能在自己的安卓手机（触屏）上玩**；B 站小游戏为远期可选项（当前需申请 / 测试权限）。
> 灵感来自《明日方舟》阿兰娜「红土拉力赛」皮肤；远期设想把拉力赛事扩展到整个泰拉大陆。
> 本文档是项目的「总纲」，定了方向、引擎、技术约束、学习路径和里程碑。后续所有实现都以此为准。

---

## 1. 项目定位

| 项 | 内容 |
|---|---|
| 项目名 | 雷姆必拓红土拉力赛（Rim Billton Redclay Rally） |
| 类型 | 3D 拉力 / 计时赛，low-poly（低多边形）美术风格 |
| 参照 | funselektor 的《art of rally》（Unity 制作，街机手感 + 风格化低模） |
| 性质 | 个人、非商业、无商业授权，不盈利、不直接使用《明日方舟》游戏素材 |
| 首发形态 | **PC + 自用安卓手机（APK / WebGL，触屏）**；B 站小游戏为远期可选（需权限） |
| 开发调试形态 | PC（Unity 编辑器内 Play），键鼠 / Xbox 手柄 |
| 远期愿景 | 赛事从雷姆必拓扩展到整个泰拉大陆 |

> 版权说明：使用「雷姆必拓 / 阿兰娜」等专有名词属于**同人二次创作**，非商业 fan game 一般被宽容，但严格说仍是 IP 衍生。为稳妥起见，**项目内部与对外可自创地名、车名**，把方舟元素作为灵感与彩蛋，避免直接复刻官方素材与设定文本。

## 2. 平台策略（本项目最关键的决定）

**近期目标调整为「PC + 自用安卓手机可玩」，B 站小游戏降为远期可选项（当前需申请 / 测试权限）。**

> 变更说明：B 站小游戏目前仍处测试、需要申请开发者权限，短期难以直接上线或真机预览。因此不再作为第一交付目标：
> - **近期**：PC（键鼠 / Xbox 手柄）+ **自己的安卓手机**（打 APK 或开 WebGL 网页），触屏能开、能跑完一条短赛道即算成功。
> - **远期（可选）**：若拿到 B 站小游戏权限，再评估用团结引擎导出微信小游戏产物转 B 站；届时注意团结引擎是 **2022.3 内核**、B 站标称 **Unity 2021.3** 的兼容差异（见 3.1）。

两条原则不变：

1. **移动端体验优先**：手机是最终使用场景之一，触屏操作、性能、包体从第一天就要考虑；PC 的键鼠 / 手柄是调试与另一平台。
2. **3D + 车辆物理 + 手机是「重负载」组合**，必须从美术、场景、物理全方位为移动端做减法。**不要**按 PC 单机规格做美术和物理，再指望「优化一下就能上手机」。

交付优先级：

- **P0（第一目标）**：安卓手机上触屏能开、跑完一条短赛道的 low-poly 拉力原型。
- **P1**：PC 上的键鼠 / 手柄调试版（开发期测手感）。
- **P2**：内容扩展、美术打磨、排行榜等。
- **P3（可选 / 远期）**：B 站小游戏上线（需权限）。

## 3. 引擎与技术栈（已定，不再纠结）

### 3.1 引擎：团结引擎 Tuanjie（基于 Unity 2022.3 LTS）

> 更新（项目实际已采用）：使用**团结引擎（Tuanjie，Unity 中国本地化引擎，内核基于 Unity 2022.3 LTS）**，而非原生 Unity 2021.3。它对国内小游戏平台（微信 / 抖音等）有较好的发布链路，更贴合本项目「发国内小游戏」的定位。

理由：
- B 站小游戏官方支持引擎仅 **Cocos Creator / Layabox / Egret / Unity**；**Godot 不在列表内，直接排除**。
- 团结引擎 = Unity 内核 + 国内小游戏发布链路，是同类中**唯一既能做 3D 车辆、又能产出国内小游戏**的成熟选项；《art of rally》本身也是 Unity 系制作。
- 中文教程与资源最多，对零基础最友好。

> ⚠️ **待验证（本项目最高平台风险）**：B 站官方适配方案标注的是 **Unity 2021.3.x**，而团结引擎基于 **2022.3 LTS**，两者的小游戏产物链路不一定完全一致。**务必在投入内容制作前，先做一次「空场景导出打通」验证**：团结引擎构建微信小游戏产物 → 用 B 站开发者工具转成 B 站小游戏 → 真机运行。若走不通，再评估改用原生 Unity 2021.3 专做 B 站版本。

> 为什么不用其他：
> - Unreal 5：对 low-poly 是杀鸡用牛刀，编辑器极重，无法直接发 B 站小游戏；
> - Godot 4：轻、免费，但发不了 B 站小游戏（硬指标下否决）；
> - Cocos Creator：适合 H5 小游戏、包体小，但 3D 车辆物理与生态远弱于 Unity，且 low-poly 3D 拉力不是它的强项。
>   —— 仅当后续发现 Unity WebGL 方案在手机上确实走不通时，才考虑把「B 站版」用 Cocos 另做一个更轻的简化版（PC 版仍用 Unity）。

### 3.2 必装模块与关键包

- 团结引擎 Hub + 团结引擎 **1.6.14**（内核 2022.3.61t15，安装时勾 **WebGL Build Support**；真机 Android 测试再装 **Android Build Support**）——已装。
- **渲染管线**：当前项目模板为**内置管线**（Built-in），M1 原型直接用它开发；上手机前再评估迁移 URP（原型脚本已按管线自适应，无需改动）。
- **Input System**：统一处理触屏、键鼠、手柄输入。**M1 原型先用旧版 Input Manager**（键盘 + 屏幕虚拟按键零配置可用）；需要手柄时再迁移。
- **uGUI（com.unity.ugui 包）**：2022.3 起需显式安装，屏幕按钮 / 计时 UI 都依赖它——已加入 manifest。
- **Cinemachine**：M1 原型用自写的 ChaseCamera（追尾 + 随速 FOV，无需装包）；后续需要多机位 / 轨道相机时再装。
- **TextMeshPro**：需要中文 UI 文字时再上（M1 先用旧版 Text 显示英文，避免内置字体缺中文字形）。
- **B 站小游戏开发工具（IDE 1.4.0+）** 与 Unity→小游戏的构建插件（远期、拿到权限再装）。

## 4. 美术与技术风格（low-poly，且为移动端做减法）

### 4.1 美术路线

- **先不要学 Blender**。用 Unity 内置基本体（Cube / Cylinder / Capsule）拼一辆「方块车」，用平面+坡度拼赛道，先把车开起来。
- 素材用 **Kenney.nl 的免费 CC0 低模资源包**（车辆、道路、自然道具等，风格和 art of rally 接近，可商用可修改，零版权顾虑）。
- 配色走**红土色调**：赭红地面 + 暖黄天光 + 低饱和度植被，营造「雷姆必拓红土」氛围。
- 等原型跑通、确认喜欢，再考虑进 Blender 做原创模型。**美术永远排在「能开」之后。**

### 4.2 移动端性能预算（初版目标，后续按真机调整）

| 指标 | 目标值 |
|---|---|
| 同屏三角面数 | ≤ 10 万（尽量 5 万以内） |
| Draw Call | ≤ 100–150（用材质合并 / 图集） |
| 纹理 | 图集打包、压缩（ASTC/ETC2），少用大图 |
| 光照 | 单方向光 + 烘焙 / 顶点色；**实时阴影关掉或只用 blob 阴影** |
| 粒子 | 尘烟用对象池，限制数量 |
| 相机 | 雾效做远景剔除，小场景分块 + 遮挡剔除 |

### 4.3 B 站小游戏约束（重要，发布期会卡人）

- **包体与分包**：小游戏主包体积上限很小（同系平台量级：主包约 4MB、总量约 30MB 级别，**具体以 B 站后台为准**）。必须用**分包加载**，首屏只放最小可玩内容。
- **首屏优化**：B 站把「首屏渲染」列为重点，需接入首屏配置/占位图，否则影响审核与体验。
- **必接项**：启动埋点（`launchSuccess`）、侧边栏复访、桌面快捷方式等，发布前按后台清单逐项接。
- **审核**：注意实名、内容合规等平台要求。

## 5. 核心玩法与 MVP 范围

### 5.1 核心循环（第一版）

**计时赛（Stage Time Trial）**：选一条赛段 → 从起点跑到终点 → 记录用时 → 刷新个人最佳 / 解锁下一段。

### 5.2 MVP 最小可玩版本（只做这些，别贪多）

- **1 辆车**（方块拼的低模车即可）
- **1 条短赛段**（低模地形 + 一条赛道样条曲线）
- **计时 + 到达终点结算**
- **触屏操控**：屏幕左下「左/右转向」按钮，右下「油门/刹车」；可先做**自动油门**简化。
- **追尾相机**（Cinemachine）+ 可选固定俯视/第三人称
- **尘烟粒子**做手感反馈
- 横屏显示

> 目标只有一个：**开着爽**。手感对了，低模也好看；手感不对，画面再好也没人玩。

### 5.3 手感要点（此类游戏的成败核心）

- 物理先做**街机向**（抓地强、易漂移、宽容），后期再加深拟真度；
- 转向、加速度、漂移反馈要跟手；
- 相机跟随的阻尼与视野变化，占「手感」的一半。

## 6. 从零开始的学习路线（务实版）

> 前提：编程与建模近乎零基础。**不要试图先「学完 Unity」再开工**，边做边学最快。

### 第 0 阶段 · 环境与手感（约 1 周）
- 装团结引擎（Tuanjie，含小游戏 / WebGL 构建模块）。
- 跟做官方入门教程 **Unity Essentials / Roll-a-Ball**，熟悉编辑器界面：Scene、Hierarchy、Inspector、Play、组件、预制体。

### 第 1 阶段 · 站在现成模板上（约 1–2 周）
- ~~打开 Unity 官方 **Karting Microgame** 赛车模板~~（团结引擎 Hub 无该模板 → 改为直接自建原型：`Assets/Editor/RedclayPrototypeBuilder.cs` 一键生成可玩场景）。
- 原目标不变：这是零基础最快建立「我能做出赛车游戏」信心的一步。
- 顺带把 Kenney 的免费车/场景素材导入试玩。

### 第 2 阶段 · 自己的最小原型（约 2–4 周）
- 用基本体拼一辆车 + 用样条/平面做一条短赛道。
- 接入 Input System：PC 键鼠/手柄 + 触屏按钮两套输入。
- 做计时、到达判定、简单 UI。
- 目标：**手机上（或编辑器模拟手机分辨率）能完整跑完一条赛道并出成绩。**

### 第 3 阶段 · 打磨与内容（约 3–6 周）
- 手感调参、相机优化、尘烟/音效、UI 美化。
- 增加第二条赛段、车辆颜色/涂装、个人最佳成绩存档。

### 第 4 阶段 · 手机打包与发布（约 1–3 周）
- **打包安卓 APK**（或 WebGL 网页），传到自己的手机上安装 / 打开，触屏跑通。
- 移动端性能优化（面数 / Draw Call / 纹理压缩 / 发热与帧率），必要时简化场景。
- （可选 / 远期）若拿到 B 站小游戏权限，再按 [Unity 适配方案](https://miniapp.bilibili.com/small-game-doc/engine/unity-v2) 走微信小游戏产物 → 转 B 站小游戏。

> 时间仅为参考，取决于每周实际投入。**每周能稳定投入多少小时，比「计划多完美」更重要。**

## 8. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 3D 拉力在手机小游戏性能吃紧 | 极简美术、短赛道、减少刚体、必要时改固定视角；尽早真机测 |
| 新手想太多、做太少 | 强制里程碑：先让「方块车跑完一条赛道」，其余全延后 |
| 无美术能力 | Kenney CC0 素材 + 基本体，原创模型延后到 M2 之后 |
| 包体超标 | 分包加载 + 图集 + 压缩纹理，首屏最小化 |
| 平台规则变动 | 以 B 站官方文档与后台清单为准，发布前逐项核对 |
